# 博客平台稳定性与一致性修复设计

## 背景

博客平台定位为本地学习和作品集项目，采用单实例部署，不追求多实例高可用。

当前主要问题集中在四个方面：

- 默认配置存在安全和初始化风险。
- MySQL、Redis、Elasticsearch 和缓存之间缺少明确的数据职责。
- 热门榜、搜索可见性和通知幂等存在一致性缺陷。
- 前端路由生命周期和评论接口缺少可扩展性设计。

本设计在保持技术栈和单实例边界不变的前提下，修复阻断性问题，并建立可解释、可测试的一致性模型。

## 目标

- 全新环境能够通过 Compose 一次完成初始化。
- 不再使用公开的默认 JWT 密钥。
- 隐藏、删除或转草稿的文章不能继续从搜索和热门榜访问。
- 热门榜刷新期间始终返回完整结果。
- 点赞、编辑和隐藏后，文章详情缓存能够正确失效。
- 重复消息不会生成重复通知。
- 文章详情切换时不会显示旧文章。
- 评论接口支持分页，避免一次加载全部评论。
- 关键行为具备自动化测试和可执行的验证步骤。

## 非目标

- 不实现多实例调度协调。
- 不引入事务 outbox、投递状态机或消息中继。
- 不保证 RabbitMQ 故障期间通知零丢失。
- 不实现评论、收藏和浏览量的加权热度公式。
- 不引入分布式锁解决跨实例缓存一致性问题。
- 不重构与上述问题无关的前后端模块。

## 数据职责与一致性模型

### MySQL

MySQL 是业务事实来源，负责保存：

- 用户、文章、评论、点赞、收藏和通知。
- 文章正文与作者信息。
- 文章状态和可见性。
- 浏览量的最近一次可靠快照。

文章可见性始终由 MySQL 的 `status` 和 `hidden` 决定。

### Redis

Redis 保存可重建的派生状态：

- `blog:view:count:{articleId}`：文章实时绝对浏览量。
- `hot:articles`：当前热门文章 ZSet。
- Spring Cache 文章详情缓存。

Redis 数据丢失后，浏览量和热门榜可以基于 MySQL 重建。

### Elasticsearch

Elasticsearch 是只读搜索索引，只保存允许公开搜索的文章。

搜索接口必须按 MySQL 可见性进行最终过滤，不能仅依赖 ES 文档状态判断权限。

### 一致性目标

- 用户、文章、评论、点赞、收藏和通知立即一致。
- 浏览量、热门榜、文章缓存和搜索索引允许短时延迟。
- 所有派生状态都必须具备自动修复或重建路径。

## 安全与启动设计

### JWT

- `application.yml` 不再提供可用的默认密钥。
- `JWT_SECRET` 必须显式配置，长度至少 64 字节。
- 后端启动时校验密钥配置，不满足要求时拒绝启动。
- `.env.example` 只提供空值和生成命令，不包含真实可用密钥。
- README 说明本地首次运行步骤和密钥轮换方式。

### 数据库初始化

- `blog/src/main/resources/sql/init.sql` 作为全新环境唯一基线。
- 历史迁移文件移动到 `blog/src/main/resources/sql/migrations/`。
- Compose 只自动执行基线，不自动执行历史迁移。
- 已有本地数据库的手动升级步骤写入迁移文档。

### 本地网络

- MySQL、Redis、RabbitMQ 和 Elasticsearch 的宿主机端口默认绑定 `127.0.0.1`。
- CORS 只允许本地前端地址，例如 `http://localhost:5173` 和 `http://localhost`。
- 开发密码继续允许简化配置，但只用于本机环境。

### 请求大小

- 文章正文上限统一为 2MB。
- Nginx、Spring 请求体和 DTO 校验使用相同限制。
- `article.content` 从 `TEXT` 调整为 `MEDIUMTEXT`。

## 浏览量、热门榜与文章缓存

### 浏览量

- Redis 使用绝对计数保存实时浏览量。
- 首次读取时，以 MySQL 当前值作为 Redis 计数基线。
- 文章删除时同步删除对应 Redis 计数 key。
- MySQL 仅保存最近一次成功回写的快照。

### 热门榜

新增统一的维护任务，每五分钟依次执行：

1. 将 Redis 浏览量回写 MySQL。
2. 扫描 Redis 中当前有效的浏览量计数。
3. 使用临时 ZSet 构建热门榜。
4. 通过原子替换切换正式 `hot:articles`。

其他约束：

- 隐藏、删除或转草稿时立即从热门榜移除对应文章。
- 重新公开后等待下一次维护任务重新计算。
- 读取时跳过失效文章并继续取候选，保证尽量返回完整条数。
- 首页侧栏和列表页热门排序统一调用 `HotArticleService`。
- Redis 不可用时回源 MySQL。
- MySQL 增加 `(status, hidden, view_count)` 相关联合索引。

### 热度定义

热门文章继续按浏览量排序。

文档和界面文案统一改为“按浏览量”，不实现点赞、评论和收藏加权公式。

### 文章缓存

- 文章详情缓存 TTL 从一小时缩短为十分钟。
- 点赞和取消点赞提交后，清除对应文章详情缓存。
- 编辑、隐藏、公开和删除提交后，清除对应文章详情缓存。
- 浏览量继续由 Redis 单独维护，不写入文章详情缓存。

## 写入、搜索和通知一致性

### 事务后副作用

- 点赞、取消点赞、编辑、隐藏、公开和删除继续在 MySQL 事务中完成。
- 事务提交后统一处理缓存失效、ES 同步和 MQ 投递。
- 副作用失败不得回滚已经提交的业务事务，但必须记录错误并允许重试或重建。

### 搜索同步

- 发布和更新文章后写入 ES。
- 隐藏、转草稿或删除文章后删除 ES 文档。
- 搜索结果为每个命中项按文章 ID 批量回查 MySQL。
- 仅返回当前已发布且未隐藏的文章。
- 应用启动后执行一次索引全量对账，删除非公开文档并重建公开文档。
- 搜索文档增加可分词标签字段和 `authorNickname` 字段。
- 搜索覆盖标题、正文、标签和作者昵称。

搜索分页由 ES 完成，MySQL 回查只负责过滤和补充作者信息。过滤后的当前页允许出现少量空缺，后续由索引对账消除幽灵文档。

### 通知幂等

- 通知消息增加稳定 `eventKey`。
- `LIKE` 使用点赞记录 ID，`COMMENT` 使用评论 ID。
- `notification` 表增加 `event_key` 唯一索引。
- 消费者插入时遇到唯一键冲突直接忽略。
- 删除十秒时间窗口去重逻辑。

通知只保证不重复，不保证 RabbitMQ 故障期间零丢失。

## 前端生命周期与评论分页

### 文章详情

- 监听 `route.params.id`。
- 文章 ID 变化时重置文章、点赞、收藏和评论状态。
- 使用请求序号或取消机制忽略旧请求的迟到响应。
- 加载成功后滚动到页面顶部。
- 编辑和删除权限根据新文章重新计算。

### 搜索

- 后端支持作者昵称和标签搜索。
- 前端继续展示“搜索文章、作者或标签”。
- 搜索结果继续使用转义后的高亮 HTML。

### 评论分页

- `GET /api/comments` 改为分页返回一级评论。
- 默认每页 20 条。
- 查询当前页一级评论后，批量查询其子回复。
- 前端提供分页或“加载更多”。
- 评论总数和未加载状态由分页信息驱动。

接口返回结构将从评论数组调整为分页对象，前后端和类型定义同步修改。

### 页面元信息

- `html lang` 设置为 `zh-CN`。
- 页面标题改为实际站点名称。

## 错误处理与降级

- JWT 配置非法时应用启动失败。
- 数据库初始化失败时 Compose 初始化失败，不继续启动后端。
- Redis 不可用时，浏览量和热门榜回源 MySQL，文章详情缓存降级或失效。
- Elasticsearch 不可用时，搜索返回明确错误，其他功能继续工作。
- RabbitMQ 不可用时，业务数据正常提交，通知允许丢失但记录错误。
- MQ 重复投递由数据库唯一索引消除。

## 数据库变更

- 重构并保留最终 `init.sql`。
- 添加 `article.content` 为 `MEDIUMTEXT`。
- 添加热门榜回源所需联合索引。
- 添加 `notification.event_key` 和唯一索引。
- 迁移脚本只用于已有数据库，不进入 Compose 自动初始化目录。

## 测试策略

### 后端

- JWT 配置缺失和长度不足时启动校验失败。
- 热门榜临时 ZSet 原子替换。
- 热门榜失效成员回填。
- Redis 热门榜不可用时回源 MySQL。
- 点赞后文章详情缓存被清除。
- 隐藏文章无论是否残留在 ES 都不会通过搜索接口返回。
- 通知相同 `eventKey` 只插入一次。
- 文章正文 2MB 边界。
- 评论一级分页和子回复批量加载。

### 前端

- 文章详情路由 ID 变化后重新加载并重置状态。
- 旧请求迟到不会覆盖新文章。
- 评论分页和加载更多。
- 热门列表使用统一接口结果。

### 冒烟验证

删除数据卷后执行：

1. Compose 全新启动成功。
2. 注册和登录成功。
3. 发布文章后可以搜索。
4. 隐藏文章后详情、列表、搜索和热门榜均不可见。
5. 点赞后刷新详情页计数正确。
6. 热门榜刷新期间结果完整。
7. 重复投递通知不会产生重复记录。

每个批次完成后执行：

```powershell
cd blog
.\mvnw.cmd test

cd ..\frontend
npm test
npm run type-check
npx eslint .
npx oxlint .
```

## 实施批次

### 批次一：启动与安全基线

- JWT 显式配置与启动校验。
- 数据库基线、迁移目录拆分。
- 本地端口和 CORS 收紧。
- 文章正文大小统一。

### 批次二：热门榜与缓存一致性

- 统一浏览量和热门榜维护任务。
- ZSet 原子替换和失效成员回填。
- 热门接口统一。
- 索引、缓存 TTL 和点赞缓存失效。

### 批次三：搜索、写入和通知

- 搜索字段扩展和 MySQL 可见性过滤。
- 启动索引对账。
- 事务后副作用统一。
- 通知 `eventKey` 和唯一索引。

### 批次四：前端与评论分页

- 文章详情路由生命周期。
- 评论接口分页。
- 前端评论加载状态。
- 页面元信息。

## 验收标准

- 使用默认仓库配置但缺少 JWT 密钥时，后端拒绝启动。
- `docker compose down -v` 后能够一次启动成功。
- 隐藏或删除的文章无法从详情、列表、搜索和热门榜访问。
- 热门榜刷新期间不会返回残缺结果。
- 点赞后刷新详情页能够看到新计数。
- 重复通知消息不会生成重复记录。
- 快速切换文章不会显示旧内容。
- 评论接口不再一次加载全部评论。
- 自动化测试和静态检查全部通过。

## 风险与取舍

- 使用 MySQL 回查过滤搜索会牺牲少量分页连续性。
- 不使用 outbox 意味着 RabbitMQ 故障期间通知可能丢失。
- 使用单实例调度意味着不支持多实例部署。
- 使用视图计数定义热门意味着实现与原始加权公式不同，但文档会保持一致。
- 评论分页会增加接口和前端状态复杂度，但避免热门文章评论无限增长。
