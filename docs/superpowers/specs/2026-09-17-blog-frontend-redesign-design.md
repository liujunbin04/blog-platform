# 博客平台前端视觉重设计规格

日期：2026-09-17
状态：已确认
范围：`frontend/`，不改动后端接口与数据模型

## 一、背景与目标

当前前端是 Vue 3 + Vite + TypeScript + Pinia + Vue Router + Element Plus，已覆盖文章列表、文章详情、文章编辑、登录、注册和个人中心。现有界面功能完整，但主要使用 Element Plus 默认视觉，页面层级、品牌识别和响应式体验不足。

本次目标：

1. 在不改变现有功能、路由和接口的前提下，统一重设计全部前端页面。
2. 建立适合中文博客阅读、写作和社区互动的视觉系统。
3. 提升桌面、平板和移动端的可用性与信息层级。
4. 为未来可能加入的辅助能力预留组件位置，但当前不展示任何 AI 功能、AI 文案或假入口。
5. 增强 Markdown 编辑器的前端写作体验。

非目标：

1. 不接入模型、向量数据库、AI SDK 或提示词系统。
2. 不修改后端接口、数据库、搜索、缓存、排序和通知逻辑。
3. 不修改品牌名称、站点信息架构和路由结构。
4. 不替换为富文本编辑器或协同编辑器。
5. 不增加深色主题。

## 二、代码扫描结论

当前项目没有实际 AI 功能：

- `blog/pom.xml` 未引入 OpenAI、Spring AI、LangChain 或任何模型供应商 SDK。
- 控制器中没有摘要、续写、润色、自动标签、语义搜索或推荐接口。
- 搜索是 Elasticsearch 的 `multi_match` 关键词匹配和高亮，不是语义搜索。
- 热门文章是 Redis ZSet 按浏览量排序，不是个性化推荐。
- 前端 API 只有认证、文章、评论、点赞、收藏和通知调用。

因此产品的真实定位是“内容创作与社区互动博客平台”。“智能”可以作为未来规划，但不能成为当前界面的功能承诺。

## 三、已确认的设计决策

| 决策点 | 结论 |
| --- | --- |
| 产品表达 | 重点呈现阅读、创作和社区互动，不宣传现有 AI 能力 |
| 未来能力 | 通过组件结构预留位置，当前不显示不可用入口 |
| 视觉方向 | 蓝图编辑台：理性、清晰、有编辑感 |
| 编辑器方向 | 专业写作软件：文档栏、格式工具栏、编辑/预览、大纲和状态栏 |
| 个人中心方向 | 创作账本，不使用默认后台管理表格观感 |
| 技术边界 | 仅前端重构，保留现有 API、Pinia 状态和路由 |
| 实施方式 | 一次交付视觉重设计和编辑器增强 |

## 四、视觉系统

### 4.1 色彩

| Token | Hex | 用途 |
| --- | --- | --- |
| Ink Navy | `#10273D` | 主文字、深色导航、主按钮 |
| Signal Red | `#E5593F` | 关键动作、搜索高亮、状态强调 |
| Moss Mist | `#DCEAE5` | 上下文轨道、作者信息、次级区域 |
| Blueprint | `#EEF3F7` | 页面背景、分隔区域、骨架屏底色 |
| Paper | `#FFFFFF` | 内容画布、输入框和主要面板 |

补充语义色沿用 Element Plus 的成功、警告、危险色，但在页面内控制使用面积。

### 4.2 字体

- 展示标题：`Georgia, "Noto Serif SC", "Songti SC", serif`
- 正文与界面：`"PingFang SC", "Microsoft YaHei", system-ui, sans-serif`
- 数据与标签：`Consolas, "SFMono-Regular", monospace`

标题使用衬线字体建立编辑感和阅读重心；交互文本使用无衬线字体；数字、时间、阅读时长和分类标签使用等宽字体。

### 4.3 版式

- 页面最大内容宽度约 `1180px`。
- 桌面端核心页面使用“主内容 + 上下文轨道”结构，比例约为 `2:1`。
- 首页列表强调扫描效率，使用行式文章条目而不是重复的悬浮卡片。
- 详情页强调阅读节奏，正文行高不低于 `1.8`。
- 上下文轨道是唯一强识别元素，用于承载作者、标签、互动和后续扩展位置。

### 4.4 动效

- 页面与模块进入：`160–220ms` 的透明度和轻微位移。
- 轨道进入：一次方向性展开，不做持续漂浮或循环动画。
- 交互反馈：按钮、点赞、收藏和标签切换只改变必要状态。
- 所有非必要动效在 `prefers-reduced-motion: reduce` 下关闭。

## 五、全局布局与导航

### 5.1 App Shell

- `App.vue` 保留 `el-config-provider`，负责页面背景和主内容容器。
- 新增 `AppShell.vue` 统一页面最大宽度和三种变体：
  - `content`：文章列表与详情。
  - `workspace`：编辑器。
  - `auth`：登录与注册。
- 页面主区域使用语义化 `main`。

### 5.2 AppHeader

- 左侧为站点名称，使用文字按钮而非可点击的普通 `span`。
- 桌面端显示“发现”和“热榜”入口，与现有排序和列表路径保持兼容。
- 搜索框位于中部偏右，移动端折叠为搜索按钮并展开为第二行。
- 登录后保留通知、发布入口和用户菜单；未登录状态保留登录与注册。
- 所有图标按钮必须提供 `aria-label` 或可见文本。

## 六、页面设计

### 6.1 文章列表

桌面端结构：

1. 顶部为排序和搜索状态，排序使用轻量分段控件。
2. 主栏将当前列表第一篇文章作为“今日索引”重点文章。
3. 其余文章使用带分隔线的行式条目。
4. 右栏为上下文轨道，包含热门文章和主题索引。
5. 分页位于主栏底部。

实现约束：

- 不新增“精选文章”接口，首篇重点文章直接使用当前接口返回的第一条。
- 搜索状态显示可关闭关键词标签，行为与当前实现一致。
- 热门轨道加载失败不影响文章列表。
- 列表为空时，根据搜索或普通列表场景显示不同说明和动作。

移动端：

- 主内容和轨道改为单列。
- 热门与主题索引移动到文章列表之后。
- 行式条目保持标题、摘要、作者、分类、时间和数据，不展示横向滚动。

### 6.2 文章详情

桌面端结构：

1. 主栏是标题、作者信息、Markdown 正文和评论区。
2. 右栏是上下文轨道，包含作者、发布时间、阅读时长、标签、互动数据和预留扩展位。
3. 点赞、收藏和评论数量在轨道中显示；作者编辑与删除操作保持在作者信息附近。

移动端：

- 元信息在标题下方压缩展示。
- 轨道内容拆分到正文顶部，并在页面底部固定点赞、收藏、评论操作。
- 评论编辑器保持单列和完整宽度。

实现约束：

- 继续使用 `markdown-it` 的 `html:false` 配置。
- 保留现有点赞、收藏、评论、编辑和删除逻辑。
- 扩展位本次仅作为布局结构，不显示 AI 文案、按钮或禁用假入口。

### 6.3 文章编辑器

桌面端包含：

1. 顶部文档栏：返回、草稿状态、文章标题、字数、保存草稿和发布。
2. 格式工具栏：正文、标题、粗体、斜体、引用、列表、链接和行内代码。
3. 左侧文档面板：分类、标签和根据标题生成的大纲。
4. 中间编辑区：Markdown 文本输入。
5. 右侧预览区：实时渲染的正文预览。
6. 底部状态栏：字数、光标行列、编码和 Markdown 模式。

工具栏行为：

- 按钮在 textarea 当前选区中插入对应 Markdown 标记。
- 已有选区时包裹或替换选区；无选区时插入完整占位文本。
- 操作完成后恢复合理光标位置并重新聚焦。
- 工具栏增强只操作 `form.content`，不改变保存接口。

大纲行为：

- 从 `form.content` 中解析 `#` 到 `######` 的 ATX 标题。
- 忽略 fenced code block 内的井号标题。
- 点击大纲项滚动到编辑区对应行。
- 大纲为空时显示简洁空状态，不占据主要编辑空间。

状态栏行为：

- 字数为去除空白后的 Unicode 字符数，适合中文内容。
- 光标行列根据 `selectionStart` 计算。
- 编码固定显示 `UTF-8`，编辑模式固定显示 `Markdown`。

响应式：

- 平板端隐藏左侧大纲，编辑与预览通过分段控件切换。
- 移动端默认显示编辑区，通过底部分段控件切换预览、大纲和文档信息。
- 发布和保存草稿始终可见。

### 6.4 登录与注册

- 使用单页分栏：左侧是简洁的品牌信息区，右侧是表单。
- 不再使用居中的默认 `el-card`。
- 字段、校验、跳转和错误处理保持现有逻辑。
- 移动端隐藏大面积品牌区，仅保留短页眉和单列表单。

### 6.5 个人中心

- 顶部为创作账本式摘要：昵称、文章数、浏览量、获赞数。
- 两个 Tab 保持“我的文章”和“我的收藏”。
- 桌面端使用账本列表而不是默认后台表格。
- 移动端每一项分层显示标题、状态、数据与操作，避免横向滚动。
- 分页、编辑、隐藏、公开、删除和取消收藏行为保持现有逻辑。

## 七、响应式规范

| 范围 | 策略 |
| --- | --- |
| `>= 1200px` | 完整双栏；编辑器显示大纲、编辑和预览 |
| `768px–1199px` | 阅读轨道下移；编辑器隐藏大纲并使用编辑/预览切换 |
| `< 768px` | 单列布局；详情操作固定底部；个人中心改为条目列表 |

所有固定尺寸元素使用 `min-width`、`max-width`、`aspect-ratio` 或网格约束，避免动态内容改变布局。

## 八、组件与文件边界

计划新增或调整：

- `frontend/src/styles/tokens.css`
- `frontend/src/styles/element-overrides.css`
- `frontend/src/components/AppShell.vue`
- `frontend/src/components/ArticleListItem.vue`
- `frontend/src/components/ContextRail.vue`
- `frontend/src/components/EditorToolbar.vue`
- `frontend/src/components/EditorOutline.vue`
- 现有 `AppHeader.vue`、`CommentItem.vue` 和全部 views 的模板与样式

约束：

- 只有跨页面复用的结构才抽成组件。
- 页面专属结构保留在对应 view。
- 不新增全局状态 store。
- 不修改 `frontend/src/api` 和 `frontend/src/types/api.ts` 的接口契约。

## 九、状态与错误处理

- 保留现有 axios 拦截器和统一错误提示。
- 列表、详情和编辑器加载使用结构化骨架屏。
- 副轨道加载失败时保留主内容并静默降级，现有 toast 行为不变。
- 空状态必须说明原因，并在适用时提供下一步动作。
- 保留未登录跳转、401 处理、表单校验和提交中状态。

## 十、可访问性

- 页面使用 `header`、`nav`、`main`、`section` 和 `footer` 等语义结构。
- 所有仅图标按钮提供可访问名称。
- 键盘焦点使用明确的 `:focus-visible` 样式。
- 所有可操作元素键盘可达，不能依赖 hover 才能发现操作。
- 移动端触控目标不小于 `44px`。
- 文本对比度满足 WCAG AA。
- 尊重 `prefers-reduced-motion`。

## 十一、验证标准

必须通过：

1. `npm run type-check`
2. `npm run lint`
3. `npm run build`
4. 构建产物不新增大于 `500kB` 的 chunk 警告

视觉与行为检查：

1. `1440×900` 桌面端：列表、详情、编辑器、认证页和个人中心无溢出或重叠。
2. `1024×768` 平板端：轨道、工具栏和编辑/预览切换正常。
3. `390×844` 移动端：单列、底部操作、账本条目不横向滚动。
4. 搜索、清空搜索、排序、分页、点赞、收藏、评论、登录、发布和草稿保存流程不回退。
5. 编辑器工具栏插入结果正确，大纲解析与滚动正常，状态栏数据准确。
6. 键盘焦点、空状态、加载状态和错误状态可辨识。

## 十二、实施交付

交付物包括：

- 全部前端页面的新视觉与布局。
- 全局设计 token 和 Element Plus 轻量覆盖样式。
- 响应式行为。
- Markdown 编辑器工具栏、大纲和状态栏。
- 可访问性、动效和状态处理。
- 构建、lint 和关键页面人工验证结果。

本次不修改后端，不创建 AI 功能，不提交与本规格无关的重构。
